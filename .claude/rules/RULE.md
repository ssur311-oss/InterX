# RULE.md — 업무 규칙

> 코드와 AI 모두 이 규칙을 따른다. 규칙끼리 부딪히면 **위에 있는 규칙이 우선**한다.
> 아래 숫자와 서류 목록은 **예시 기본값**이다. 실제 값은 과제 협약·전문기관 지침에 맞춰 **설정 화면에서 바꿀 수 있어야** 하며, 코드에 고정하지 않는다.

---

## 0. 대원칙

1. **숫자·날짜·규칙 판정은 코드가, 말 해석과 문장 작성은 AI가 한다.**
   AI가 낸 숫자나 날짜는 관리자가 확인 버튼을 누르기 전까지 저장하지 않는다.
2. **AI는 제안만 한다.** 저장, 상태 변경, 슬랙 발송은 반드시 관리자의 버튼 클릭으로 실행된다.
3. **이 도구는 지원사업비 증빙 전용이다.** 급여, 4대보험, 주민번호, 연락처 등 개인정보는 다루지 않는다.
4. **기록은 지우지 않는다.** 처리 이력은 감사 소명의 근거다. 수정은 새 이력을 추가하는 방식으로.

---

## 1. 필요 증빙 자동 생성 (F1)

- 집행 건의 **비목·세목 × 결제 방법**으로 `doc_rules`에서 필요한 서류를 찾아 `required_docs`를 만든다.
- 결제 증빙은 결제 방법으로 정해진다: 카드 → **카드전표**, 계좌이체 → **세금계산서**.
- 규칙표에 없는 조합이면 "규칙 없음 — 확인 필요"로 표시하고 결제 증빙만 생성한다.

### 기본 규칙표 (예시)
| 비목 / 세목 | 결제 | 필요 증빙 |
|---|---|---|
| 연구재료비 | 카드 | 카드전표, 거래명세서, 검수조서 |
| 연구재료비 | 계좌이체 | 세금계산서, 거래명세서, 검수조서 |
| 연구활동비 / 회의비 | 카드 | 카드전표, 회의록, 참석자 명단 |
| 연구활동비 / 출장비 | 카드·계좌이체 | 출장신청서, 출장결과보고서, 교통·숙박 증빙 |
| 연구시설장비비 | 계좌이체 | 견적서, 계약서, 세금계산서, 검수조서, 사진 |
| 위탁·외주 용역 | 계좌이체 | 계약서, 세금계산서, 결과물, 검수확인서 |

## 2. 감사 위험 건 표시 (F2)

| 코드 | 규칙 | 기본값 |
|---|---|---|
| `WEEKEND` | 토·일·공휴일 사용 | - |
| `LATE_NIGHT` | 심야 사용 | 23:00 ~ 06:00 |
| `SPLIT` | 분할 결제 의심: 같은 날 같은 거래처에서 2건 이상, 합계가 기준 금액 초과 | 기준 금액 설정값 |
| `OUT_OF_PERIOD` | 과제 기간(시작일~종료일) 밖 사용 | - |
| `MEETING_LIMIT` | 회의비 1인당 금액 초과 (참석자 수가 있을 때만) | 설정값 |

- 위험 표시는 **"확인 필요"**라는 뜻이지 **위반 확정이 아니다.** 화면 문구도 "확인 필요"로 쓴다.
- 관리자가 확인 후 "소명 완료"로 표시할 수 있고, 소명 내용은 처리 이력에 남긴다.

## 3. 마감 일정 (F3)

- **사내 마감일 = 정산 기한 − 사내 마감 여유일(영업일 기준, 기본 5일)**
- 리마인드: 사내 마감 **D-7, D-3, D-1**
- 주말·공휴일이면 **직전 영업일**로 당긴다.
- 공통 마감일은 그 달 모든 증빙에 똑같이 적용된다. 늦어지는 건만 개별 **제출 예정일**을 가진다.

## 4. 증빙 상태 (F4)

| 상태 | 표시 | 판정 (코드 계산) |
|---|---|---|
| 제출 | ✅ | `status = submitted` |
| 제출 예정 | ⏳ M/D | `scheduled`, 오늘 ≤ 예정일 |
| **약속일 경과** | 🔴 | `scheduled`, 오늘 > 예정일 |
| 미제출 | ❌ | `missing` |
| 마감 넘는 예정 | ⚠️ | 예정일 > 사내 마감일 → 관리자 판단 필요 |

- 현황판 정렬: 🔴 → ⚠️ → ❌ → ⏳ → ✅
- "약속일 경과"와 "마감 넘는 예정"은 저장하지 않고 **볼 때마다 계산**한다.

## 5. 슬랙 메시지 붙여넣기 (F6)

1. 관리자가 슬랙 메시지를 붙여넣는다. (보낸 사람을 목록에서 고른다)
2. AI가 분류하고 날짜·사유·증빙 종류를 뽑는다. (`SKILL.md` 작업 1)
3. 어느 집행 건의 증빙인지 **후보를 보여주고 관리자가 고른다.** AI가 자동으로 연결하지 않는다.
4. 관리자가 [반영]을 누르면 예정일·상태가 바뀌고 처리 이력에 원문과 함께 저장된다.
5. 예정일이 사내 마감일을 넘으면 ⚠️ 경고를 먼저 보여준다.

## 6. 통보 / 재통보 (F7)

| 버튼 | 대상 | 조건 |
|---|---|---|
| 통보 | ❌ 미제출 | 첫 요청 |
| 재통보 | 🔴 약속일 경과 또는 통보 후에도 ❌ | 마지막 발송 후 **24시간 이후**에만 활성화 |

- 한 사람에게 보낼 내용은 **한 메시지로 묶는다.** (건마다 따로 보내지 않음)
- 같은 사람에게 **하루 2회 이상 발송 금지.**
- 문장은 AI 초안 → **관리자 미리보기·수정 → 발송.**
- 발송 기록은 처리 이력에 남긴다.

## 7. 파일명 정리 (F8)

- 형식: `과제약칭_비목_YYMMDD_금액_거래처_증빙종류.확장자`
  - 예: `자율제조_재료비_261014_2300000_OO전자_세금계산서.pdf`
- 파일명에 쓸 수 없는 문자(`\ / : * ? " < > |`)와 공백은 제거하거나 `_`로 바꾼다.
- 같은 이름이 있으면 끝에 `_2`, `_3`을 붙인다.
- 파일을 집행 건에 연결하면 해당 증빙 상태를 ✅로 바꿀지 관리자에게 묻는다.

## 8. 표기

- 금액: 화면 `2,300,000원`, 파일명 `2300000`
- 날짜: 화면 `11/3(월)`, 저장 `2026-11-03`, 파일명 `261103`
- 집행률: `42.5%`
- 시간대: Asia/Seoul

## 9. 보안

- API 키와 웹훅 주소는 `.env`·Supabase Secrets에만. AI 호출과 슬랙 발송은 **Edge Function**에서만.
- AI에 보내는 정보는 최소한: 메시지 본문, 이름, 증빙 종류, 날짜. 금액·거래처는 문장 작성에 필요할 때만.
- 데모는 **가짜 데이터만** 사용한다.

## 10. 말투 (슬랙으로 나가는 모든 문장)

- 정중하고 부드럽게. 재촉이 아니라 협조를 구하는 톤.
- **무엇이 / 왜 / 언제까지** 필요한지 반드시 포함.
- 어려우면 편하게 말해달라는 한 줄로 마무리.
