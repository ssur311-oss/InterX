# Claude Code에 아래 내용을 붙여넣으세요

기존 React + Vite + TypeScript 대시보드의 AI 도우미 영역에, 아래 명세대로 실시간 3D 컴퓨터 캐릭터 ‘모니’를 구현해줘. 계획 설명만 하지 말고 실행 가능한 코드와 확인 결과까지 완성해줘. 먼저 프로젝트의 AGENTS.md / CLAUDE.md / RULE.md 및 적용되는 SKILL.md를 읽어. 기존 앱 구조와 패키지를 확인하고 기존 업무 기능은 보존해.

## 결과물
- `AiAssistantCharacter.tsx`: 독립적으로 재사용 가능한 캐릭터.
- `AiAssistantPanel.tsx`: 캐릭터 + 기존 챗봇 UI 연결. 기존 도우미 영역이 없으면 대시보드 오른쪽 패널에 예시로 배치.
- 실제 AI 연결이 없으면 ‘대화 시연’이라고 명시하고 고정 예시 답변만 사용.
- 모델 파일 없이도 실행되도록 Three.js 기본 도형과 RoundedBoxGeometry로 캐릭터를 직접 만들어. 공개 라이브러리는 프로젝트 패키지로 설치하고 버전을 잠가. CDN에 의존하지 마.
- 같은 프로젝트에 `design/assistant-demo/character.js`와 `index.html`이 있으면 먼저 읽고 시각·동작을 기준으로 재사용해. 없더라도 아래 명세만으로 완성해.

## 외형
레퍼런스는 귀여운 아이보리색 1990년대 CRT 데스크톱 컴퓨터. 노트북이나 사람형 로봇이 아니다. 낮고 넓은 본체 위에 둥근 두꺼운 모니터가 올라가고, 모니터의 검은 유리 화면에 초록색 세로 캡슐 모양 눈 두 개가 있다. 입은 없으며 눈과 고개로 표정을 표현한다. 본체 앞에는 작은 디스크 슬롯과 붉은 배출 버튼, 전원 표시등. 옆에는 가느다란 통풍구. 곁에 유선 마우스와 작은 화분을 둘 수 있으나 좁은 대시보드 패널에서는 숨겨도 된다.

재질은 크림색 플라스틱, 둥근 모서리, 부드러운 하이라이트와 접지 그림자. 캐릭터 장면에 한해서 레퍼런스의 초록색 눈과 옅은 라벤더·회색 바닥을 허용한다. 앱 전체는 기존 디자인 토큰을 유지한다. 사진을 평면에 붙여 기울이거나 CSS perspective만 사용하는 가짜 3D는 쓰지 않는다.

## 장면과 구조
- 고정된 OrthographicCamera, 약간 위에서 보는 정면 3/4 각도. OrbitControls·자동 카메라 회전·줌 금지.
- bodyGroup(본체), headPivot(연결부 중심), monitorGroup(머리), eyesGroup(눈)으로 분리한다.
- 모니터 크기는 대략 가로 2.13, 높이 1.78, 깊이 1.25. 본체는 가로 2.55, 높이 0.5, 깊이 1.85. 비율은 시각적으로 다듬어도 된다.
- 모니터 회전축은 모니터 아래의 연결부 위치. 본체·바닥·마우스는 고정. 움직일 때 모니터 하단이 본체에 뚫고 들어가지 않도록 검사.
- 별도 WebGL canvas를 사용하고 컨테이너 크기에 맞춰 ResizeObserver로 조정. 모델이 작은 화면에서 잘리면 카메라 범위를 조정한다.

## 모션
핵심 느낌: “The character stands still and gently bobs up and down, slightly swaying left and right with a soft breathing motion, seamless loop, static camera, plain background.”

1. 기본 호흡: 6초 주기의 sin으로 머리 높이를 약 0.012 world unit만 변화. 대기 자세는 1~2도 이내의 느린 좌우 흔들림. 루프 경계에서 튀지 않게 한다. 이 요청에서는 캐릭터의 은은한 대기 모션을 명시적으로 허용한다.
2. 커서 추적: 앱 창의 pointermove를 받되 캐릭터 캔버스 중심 기준 좌표를 정규화하고 [-1,1]로 clamp. 좌우 머리 회전은 중립 기준 약 ±25도, 상하 약 ±13도. 화면 끝으로 급히 이동해도 제한 각도 안에서만 따라간다.
3. 눈이 먼저 움직이고 머리가 뒤따른다. 눈 이동은 가로 ±0.06, 세로 ±0.04 정도. 보간은 프레임 수가 아니라 delta time에 기반한 `1 - exp(-k * dt)`. 눈 k=9, 머리 k≈4.6. 머리 자세는 quaternion slerp로 자연스럽게 보간. 직접 lookAt을 매 프레임 덮어쓰지 않는다.
4. 입력 8초 후 idle: 부드럽게 주변 둘러보기 → 잠깐 마우스 쳐다보기 → 중립으로 돌아오기. 16초 내외의 느린 사이클. 커서가 움직이면 자동 추적 상태로 즉시 전환하되 자세는 부드럽게 이어져야 한다. 창 밖으로 나가면 마지막 위치에 고정하지 않고 중립 복귀.
5. 3.2~6초 간격 눈 깜빡임, 약 0.16초 동안 눈 높이를 줄였다 복원. 머리 호흡은 기본 seamless loop이고 눈 깜빡임은 자연스러운 비주기 이벤트다.
6. listening: 사용자가 입력 중이면 눈을 맞추고 움직임 축소. thinking: 고개를 살짝 갸웃, 시선 위쪽, 과한 진동이나 돌기 없음. speaking: 짧게 끄덕이고 중립 복귀. success: 눈이 웃는 아치로 바뀌고 두 번 이내 가볍게 끄덕인 뒤 돌아오기. error: 고개를 조금 기울여 주의를 표현하되 겁주는 빨간 깜빡임 금지.
7. 상태 우선순위: 정지/접근성 > 명시적 대화 상태 > 커서 추적 > idle. 대화 상태와 커서가 서로 머리 회전을 덮어쓰지 않게 단일 상태 머신으로 관리한다. 인사·성공 동작 종료 후 자동 복귀.

## 대시보드 연결
컴포넌트 props는 최소 `state: 'idle'|'listening'|'thinking'|'speaking'|'success'|'error'`, `paused`, `className`. 옵션으로 `pointerTracking`을 둔다. 캐릭터가 앱의 데이터 저장·증빙 상태 변경·슬랙 발송을 실행하면 안 된다. AI 결과는 관리자가 확인한 뒤 반영한다는 RULE.md 정책을 유지해.

오른쪽 AI 도우미 패널 상단에 약 280×220 크기로 두고, 아래에 대화·질문 예시·입력창 배치. 동작 비교를 위한 별도 데모 페이지에는 큰 장면과 ‘자동 반응 / 혼자 놀기 / 인사 / 생각 중 / 완료 / 움직임 멈추기’ 버튼을 둬. 실제 제품 패널에는 개발용 제어 버튼들을 노출하지 마.

## 성능·접근성·수명 관리
- dpr 최대 1.5~1.75. 프레임 delta를 0.05초 이내로 제한. 매 프레임 React setState 호출 금지. ref로 애니메이션 상태 관리.
- document.hidden 또는 IntersectionObserver상 화면 밖이면 렌더링과 모션 시간 진행 정지.
- `prefers-reduced-motion`이면 기본 정지. 눈에 보이는 ‘움직임 켜기/멈추기’ 제공.
- 웹GL 실패 시 정적 캐릭터 또는 설명과 재시도 안내를 보여주되 챗봇은 계속 쓸 수 있게 한다.
- effect cleanup 시 rAF, 모든 listener, ResizeObserver, IntersectionObserver, timeout 제거, geometry/material/texture/renderer.dispose. StrictMode에서도 canvas 중복과 루프 중복이 없어야 한다.
- 터치에서는 pointerdown으로 시선 반응, 스크롤을 가로채지 않는다. 상태를 색상만으로 전달하지 않고 텍스트도 표시.
- 채팅 입력값은 textContent 또는 React 텍스트로 렌더. innerHTML로 사용자 입력을 삽입하지 않는다.

## 검증과 완료 기준
실제 브라우저로 실행해 스크린샷을 확인하고, 아래 동작을 검증해. 타입 검사와 프로젝트 빌드도 통과시켜.
- 커서 좌→우, 상→하에 따른 머리 각도 변화와 제한 범위.
- 8초 무입력 idle 진입과 커서 이동 시 복귀.
- thinking→success→auto 전환 및 연속 버튼 입력에도 한 모션만 활성화.
- 정지 시 머리·눈·호흡 모두 정지, 재개 시 튀지 않음.
- reduced-motion 기본 정지, 작은 화면에서 모델·채팅 잘림 없음.
- 대시보드 다른 기능과 폼 조작에 간섭 없음, console error 없음.

최종에는 실행 위치, 구현 내용, 실제 확인한 항목과 미확인 한계를 짧은 한국어로 알려줘. 실시간 3D 데모와 실제 생성형 AI 연결을 혼동해서 완료 보고하지 마.
