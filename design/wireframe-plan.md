# 증빙 마감 도우미 — 와이어프레임 제안

## 설계 방향
관리자가 아침에 들어와 오늘 처리할 증빙을 찾고, 직원의 답변을 반영한 뒤, 남은 서류를 요청하고 마감하는 순서로 구성한다. 기본 단위는 집행 건이며 상세 안에서 각 증빙을 관리한다. 홈의 수치는 서로 겹칠 수 있는 업무 큐이므로 합산하지 않는다. 화면의 데이터는 2026-10-25 기준 가상 예시이며 실제 서비스와 연결되지 않는다.

## 페이지 분류와 업무 효율
| 메뉴 | 담당하는 질문 | 핵심 구성 | 근거 |
|---|---|---|---|
| 오늘 할 일 | 지금 무엇부터 처리할까? | 약속일 경과·오늘 예정·확인 필요 요약, 우선 처리 목록, 가까운 마감 | F2·F4. 그래프보다 조치 대상 우선 |
| 증빙 관리 | 어떤 건에 무엇이 부족한가? | 과제→사람 필터, 상태 탭, 집행 표, 상세 패널 | F1·F2·F4·F9. 여러 서류를 한 집행 건 안에서 비교 |
| └ 엑셀 등록 | 집행 내역을 어떻게 시작할까? | 업로드→열 연결→오류 검토→등록 | F1. 등록 후 관리로 돌아가는 하위 흐름 |
| 마감 캘린더 | 언제까지 처리해야 하나? | 공통 마감·개별 예정·리마인드 구분, 일별 상세 | F3·F5. 공통 기한과 개인 약속을 혼동하지 않음 |
| 슬랙 업무 | 답변을 어떻게 기록하고 요청할까? | 받은 메시지 / 통보·재통보 탭 | F6·F7. 수신은 붙여넣기, 발송은 미리보기 후 관리자 실행 |
| 파일 정리 | 파일이 어떤 증빙인가? | 파일→집행 건·증빙 연결→새 이름→ZIP | F8. 이름 변경과 제출 상태 변경을 별도 확인 |
| 설정 | 어떤 기준으로 판단하나? | 과제·사람·증빙 규칙·위험 기준·마감·슬랙 연결 | 규칙값을 코드에 고정하지 않고 관리 |
| 예산 현황 (추후) | 얼마를 썼고 남았나? | 과제·비목별 예산·집행·잔액 | F10. 증빙 제출 상태와 분리 |
| 로그인 | 누가 접근하나? | 관리자 계정 로그인 | 단일 관리자. 직원 가입 화면 불필요 |

처리 이력은 별도의 최상위 메뉴 대신 증빙 상세에 둔다. 원인이 되는 집행 건과 원문을 함께 볼 수 있고 화면 이동을 줄인다. 전체 이력 조회는 증빙 관리의 확장 기능으로 고려한다.

## 캡처에서 가져온 것과 조정한 것
| 캡처 | 참고 요소 | 적용 | 제외·변형 이유 |
|---|---|---|---|
| 1 | 상단 요약 + 하단 목록 | 오늘 할 일의 업무량 요약 | 투자 그래프 대신 실제 처리할 증빙. 검은 프로모션 카드 제외 |
| 2 | 파일 목록 + 오른쪽 상세·활동 | 증빙 상세, 파일 연결 | 두 겹 사이드바 대신 이름이 있는 단일 메뉴. 우측 패널은 선택할 때만 표시 |
| 3 | 상태별 구획 | 증빙 상태 탭과 상태 표식 | 칸반 기본 사용 안 함. 40건과 여러 서류는 표가 비교에 유리하며 드래그로 제출 처리하지 않음 |
| 4 | 조건을 좁히는 필터 | 과제→사람, 상태·검색 | 필터는 표 위에 배치해 중앙 작업 폭 확보. 추천 카드·장식 그래프 제외 |
| 5 | 지속적인 내비게이션, 기간 선택 | 고정 메뉴·월 범위 표시 | 흐린 글자와 입체 그림자를 없애 판독성 확보 |

## 화면 구조
```
고정 메뉴 │ 현재 페이지 / 기준 월 / 데모 안내
          │ 제목 + 설명                       주요 행동 1개
          │ 상태 요약 또는 작업 단계
          │ 필터 / 상태 탭
          │ 집행 건 표                  │ 선택한 건 상세
          │                             │ 필요 서류
          │                             │ 소명 / 처리 이력
```
홈은 업무 큐 + 가까운 마감, 캘린더는 월 달력 + 선택일 일정, 슬랙은 원문 + 검토 결과, 파일 정리는 연결 표 + 새 이름으로 각각 작업에 맞춰 변형한다.

## 반드시 유지할 업무 규칙
- 화면상 우선순위는 약속일 경과 → 마감 넘는 예정 → 미제출 → 제출 예정 → 제출. 증빙별 계산 결과를 보여준다.
- 감사 위험은 위반 확정이 아닌 ‘확인 필요’. 소명 내용과 완료 처리는 이력에 남긴다.
- 공통 마감은 정산 기한에서 영업일 기준 여유일을 빼고, 주말·공휴일 리마인드는 직전 영업일로 당긴다. 시안의 일정은 예시이며 실서비스에는 공휴일 달력과 계산 검증이 필요하다.
- AI 추출 결과는 저장 전 제안이다. 보낸 사람·원문·증빙 종류·날짜·사유·집행 건 후보를 관리자가 확인한다. 불명확한 값은 확인 필요로 남긴다.
- 통보는 사람별 묶음. 재통보는 마지막 발송 24시간 이후이며 같은 사람에게 하루 1회까지만. 최종 발송 전 대상·내용·채널을 보여준다.
- 파일 연결 후 제출 상태 변경은 별도 선택. 동명 파일은 _2, _3으로 구분한다.
- 처리 이력은 삭제·덮어쓰기 대신 새 이력을 추가한다.

## 시안에서 눌러볼 수 있는 것
왼쪽 모든 메뉴, 홈 업무량, 과제·사람·상태 필터, 검색과 빈 결과, 집행 상세, 캘린더 날짜, 슬랙 탭과 검토 단계, 엑셀 단계, 설정 탭, 파일 연결 확인, 설계 설명.

이 HTML은 화면과 흐름을 합의하는 시안이다. 실제 AI 호출·슬랙 전송·엑셀 해석·ZIP 생성·로그인·영구 저장은 구현하지 않으며 버튼에 ‘시연’을 표시한다. 예산은 추후 화면이다. 실제 앱 소스는 변경하지 않는다.
